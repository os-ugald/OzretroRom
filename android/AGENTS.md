# Oz RetroRom — Agent Entry Point

Oz RetroRom is developed as a real product. Agents must use repository evidence and the modular governance under `docs/ai/`.

## Mandatory startup

1. Read `docs/AI_PROJECT_MASTER.md` for changing project state.
2. Read `docs/PROJECT_DASHBOARD.md` for the current compact snapshot.
3. Read `docs/ai/AI_CONSTITUTION.md` and `docs/ai/WORKFLOW_GATES.md`.
4. `git fetch origin --prune`; inspect branch, HEAD, upstream, divergence and working tree **before assuming the local clone is newest**.
5. Identify one active Gate and one next step.
6. Load only the relevant specialist role files from `docs/ai/roles/` and applicable protocols from `docs/ai/protocols/`.
7. Inspect affected architecture/source before editing.
8. Research unstable external facts from primary/official sources.
9. Make the smallest coherent change that advances the Gate while preserving validated behavior.
10. Validate applicable Gates; `NOT RUN` is never `PASS`.
11. Update `AI_PROJECT_MASTER.md` and Dashboard in the same meaningful iteration.
12. Before Windows↔Termux handoff: review, commit, push, fetch and verify `HEAD == @{upstream}`.

## Role index

See `docs/ai/README.md`. Roles are professional capabilities, not independent personas. Cross-domain tasks activate several roles but still produce one coherent decision path.

## Non-negotiable prohibitions

Do not invent Android APIs/packages/Activities/Intents, emulator contracts, RetroArch/libretro cores, ROMgi routes/formats/endpoints, game identities or review scores. Do not equate Build with Interaction/Visual/Device validation. Do not silently discard recoverable partials, incomplete multidisc state or user-owned content. Do not use destructive Git operations without explicit authorization.
